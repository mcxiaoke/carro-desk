## 2026-10-25 20:18:08 — fix(awake): two-step state write ordering, user-suppression semantics, strict time parsing (Batch 4, H4+AW-2+AW-3)

代码审查报告 H4/AW-2/AW-3 修复（Awake 跨线程状态与输入解析）：

- **H4** IPC 命令 handler 在线程池线程写 AwakeService 状态，与 UI 线程 1 秒 tick 读同一组无锁字段。修复方式为**写序 + volatile 最小修复**（曾尝试 Dispatcher 封送，但同步 Invoke 会让命令 handler 依赖 UI 泵、在部分宿主下阻塞/死锁，故回退）：`SchedulePowerOff` 先写 `_pendingFireAt` 再写 `_pendingAction`、`SetTimed`/`SetUntilTime` 先写 `_expireTime` 再写 `_mode`——读方以闸门字段进入判定，x86-TSO 保证看到闸门翻转时必已看到先写的时刻值；`_mode`/`_pendingAction` 声明 volatile 防重排。消除"刚调度的 sleep 被立即执行 / 刚下达的 awake.on 被立即撤销"两类竞态。`CancelPendingPowerAction` 原写序（先清 action）已正确，保持不变。
- **AW-2** 设置窗口保存"关闭"不再 `ResetUserSuppression()`（与托盘 `SetPassiveByUser` 同语义）：目标进程仍在运行时不再出现"刚关闭 5 秒内被进程联动重新拉起"。
- **AW-3** "保持至指定时刻"输入改用 `DateTime.TryParseExact(HH:mm[:ss])` 严格解析：此前 `TimeSpan.TryParse` 把纯数字 "18" 解析为 18 天，机器可能被保持唤醒数周。
- 新增回归测试 `AwakeMarshallingTests`（3 项：两步写顺序、闸门字段 volatile、严格时间解析——源码断言式，防回归）。
- 验证：`dotnet build` 0 警告 0 错误；`dotnet test` 403 通过 / 0 失败（上一批 400 + 新增 3）。

## 2026-10-25 20:08:56 — fix(tasks): persist Batch-2 fields, session-scoped catch-up, editor field preservation (Batch 3, S3+M3+H1+M4)

代码审查报告 S3/M3/H1/M4 修复（任务系统持久化与字段保全）：

- **S3** `TaskConfigService` 补齐 Batch-2 字段的序列化与解析：options 的 `encoding`/`runAtStartup`/`catchUpMissed`、action 的 `env`（对象形式，兼容 `"KEY=VALUE"` 数组形式）。此前四个字段 UI 可设、模型可消费、唯独不落盘——保存即丢、手改 JSON 无效。`TaskDefinition.Validate` 新增 encoding 枚举校验（与 TaskRunner 消费集合一致），未知值不再静默按 UTF-8 处理。
- **M3** "启动补跑"统一收口到 `TaskSchedulerService.ApplyCoreLocked`：以 `_firedStartupTasks` 作会话级集合（reason 以 `startup:` 开头即记录），每会话对 `runAtStartup` 的 interval 任务与 `catchUpMissed` 且当天触发点已过的 daily 任务投递一次。`DailyTrigger` 构造不再按 catchUp 跳过防误触初始化、`IntervalTrigger.Start` 不再无条件立即触发——触发器重建（任何配置重载）不再自带补发，消除"连续保存 N 次执行 N 次"。
- **H1** `TaskEditDialog` 编辑既有任务时：工作目录回填改为显示有效值（options.workDir 优先，与 `EffectiveWorkDir` 一致）；保存时清空 `options.workDir`（统一由 `action.workDir` 承载，避免旧值压过用户新改动）；从源任务透传 UI 未暴露的 `StableUptimeSec`（否则编辑一次就被重置为默认 60）。
- **M4** `TaskEditDialog` 的 detach 测试运行句柄保存到 `_testRunHandle`："停止"按钮直接终止常驻测试进程，`OnClosing` 兜底终止——修复测试进程脱管（不可停、关窗不终止）；`_testCts` 补 Dispose。
- 新增回归测试 `TaskBatch2FieldsTests`（4 项：Batch-2 字段 Save/Load round-trip、未知 encoding 校验、daily/interval 触发器重建不自带立即触发）；`CarroDesk.Tests.csproj` 显式注册。
- 验证：`dotnet build` 0 警告 0 错误；`dotnet test` 400 通过 / 0 失败（上一批 396 + 新增 4）。

## 2026-10-25 20:00:32 — fix(pin): stale pending credentials and digits-only PIN (Batch 1, S1+S2)

代码审查报告 S1+S2 修复（PIN 凭据链路）：

- **S1** `HostPinService.VerifyCore` 新增 stale pending 检测：配置持有有效凭据且与 pending 不一致时丢弃 pending、以配置为准。修复"首次运行向导设置过 PIN 后，经配置编辑器修改 PIN，宿主重启前新 PIN 验证失败、旧 PIN 继续有效"（锁屏/退出确认/IPC 全部命中）。配置无有效凭据（SetNewPin 未落盘窗口期）时仍保留 pending，不破坏既有 P2-4 行为。

- 新增回归测试 `PinCredentialTests`（5 项：pending 一致路径、配置外部更换后新旧 PIN 语义、纯数字校验、语言包 key 存在）；`CarroDesk.Tests.csproj` 显式注册。
