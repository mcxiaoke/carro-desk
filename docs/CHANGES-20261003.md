**中危（健壮性 / 正确性）**

- 能力注册表改为原子重建（失败保留原有效表）；`int` 参数遇 JSON 小数按整数语义收敛、非整数明确报错。
- `log.txt` 超 1MB 轮转；空闲服务"用户活跃"改为真正的边沿触发。
- CLI `ctl` 与父控制台回显统一 UTF-8；服务控制兼容访问被拒并对 `services.status` 逐服务隔离；过渡态给出明确错误。

- 测试：修正恒真断言与名不副实用例名、补齐语言状态兜底清理；新增 3 个回归用例（能力表原子重建、int 参数收敛、非整数拒绝）。

## 2026-10-03 10:51 — Awake 模块新增延迟睡眠/关机能力（awake.sleep / awake.shutdown）

- **新增 4 个 IPC 能力**（CLI 与 MCP 经能力表自动获得，无需客户端改动）：
  - `awake.sleep`：延迟睡眠（S3）。`seconds` 参数（0-86400）缺省 30 秒，为 MCP agent 回复用户预留时间；返回预计睡眠时刻；
  - `awake.sleep.cancel` / `awake.shutdown.cancel`：取消对应的待执行电源动作；
  - `awake.shutdown`：延迟关机，`seconds` 缺省 30；Risk 定为 Privileged。执行时借系统 `shutdown.exe /s /t 0`，对有未保存文档的应用弹系统标准提示而非强杀。
- **单一待执行槽位设计**：睡眠与关机共用一个 pending 动作，新调度替换旧调度，从结构上避免"睡眠唤醒后过期关机定时器立即触发"的隐患。
- **AwakeService 实现**：复用既有 1 秒 DispatcherTimer 做到点检查；睡眠到点先 `SetPassive()` 撤销 `ES_SYSTEM_REQUIRED/ES_DISPLAY_REQUIRED` 保持唤醒状态再经 `SetSuspendState`（powrprof.dll，标准用户可用，保留唤醒事件）入睡；执行体在后台线程（`SetSuspendState` 会阻塞到唤醒）。`awake.off` 不牵连已调度的电源动作。
- **`awake.status` 扩展**：新增 `pendingAction` / `pendingFireAt` / `pendingSecondsRemaining` 字段（无待执行动作时为 null）。
- 已知边界：未决电源动作依赖宿主进程存活，宿主重启后丢失（与保持唤醒运行时状态不持久化语义一致）。
- 测试：`AwakeCapabilityTests` 扩至 15 例（命令全集/Risk/范围校验/调度替换/取消/无待执行取消无操作/awake.off 不牵连），全量 312 例通过。
