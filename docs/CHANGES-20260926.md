## 2026-09-29 09:35 — 常驻任务 B2+B3：单实例互斥 + 守护重启（对标 systemd/pm2/supervisord/任务计划）

- **B2 单实例互斥**（`options.singleInstance`，仅 detach）：`TaskSingleInstanceMutex` 持有 `Local\CarroDesk.Task.<name>` 命名互斥体，跨宿主重启有效。判定协议三层——**进程内登记表先行**（Mutex 有线程亲和，同线程重复 WaitOne 会重入成功而误判"可获取"，测试中实测复现，本进程唯一性只能靠登记表）、`createdNew=false` 默认视为已占用、`AbandonedMutexException` 视为前持有者死亡安全接手（防宿主崩溃后任务永久无法启动）。冲突启动返回 `StartSkippedSingleInstance(2)`：不算失败、不计数、不通知。释放走 Dispose 弃置（abandoned），不调 ReleaseMutex（线程亲和不可靠）；Stop() 兜底释放，watcher 完成自释放句柄。
- **B3 守护重启**（`restart: on-failure` + `restartDelaySec`/`restartLimit`/`stableUptimeSec`）：方案对标 §10.1 业界表格——取 pm2/supervisord 的"连续失败计数 + 稳定存活复位"模型 + systemd 的"熔断标记 + 显式复位"，参数形态参考 Windows 任务计划（固定间隔 + 次数上限，不做指数退避）。失败定义 = 非 0 退出/被第三方杀/启动失败；`stableUptimeSec`（默认 60s）内存活过的退出与成功退出都复位计数（防长稳后偶发崩溃被历史连坐）；连续失败超 `restartLimit`（默认 3）**熔断标记失败**：停止自动重启、recent 记 `marked`、一次性通知、UI 状态栏显示"已标记失败"；复位 = 保存任务（Reload 清守护状态）/手动或热键运行/宿主重启。重启延迟期内槽保持占用（Handle 置 null）防并发拉起，`TryStop` 升级为"杀实例 + 取消挂起重启"（systemctl stop 语义）。重启不做条件重判（When 只约束触发拉起）。
- **调度器实现**：`SupervisionState`（计数/标记/最近退出码）按任务名管理，Apply/Reload 全量清空（配置变化 = 用户干预信号）；`HandleDetachFailure → RestartContinue` 链在启动失败时递归直至预算耗尽；接口新增 `GetSupervision` 返回 `TaskSupervisionInfo`。校验拒绝 restart+非 detach、singleInstance+非 detach 及三参数越界（模型层 + 编辑器双层）。
- **编辑器**：detach 表单增加"意外退出自动重启 + 间隔/次数"；状态栏显示熔断标记与复位提示；测试运行遇单实例冲突给出明确提示。
- **文档**：设计文档 v1.2——§10 守护完整设计（含 systemd/pm2/supervisord/任务计划/SCM 对标表）、§12 单实例三层协议、场景矩阵增补 S21~S25；AUTORUN-DESIGN.md 同步选项；tasks.sample.json 样例 8 补守护与互斥示例。
