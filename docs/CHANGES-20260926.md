## 2026-09-28 15:00 — 实施 IPC 设计 S1+S2：命令内核 + 命名管道控制通道

- **S1 命令内核**（`src/Core/Commands/`、`src/Host/Commands/`）：`CommandRisk/CommandParam/CommandDescriptor/CommandRequest/CommandResult/ICommandProvider` 契约；`CommandRegistry`（白名单本体，大小写不敏感唯一）；`CommandHost`（分发器，校验顺序不可调换：存在性 -32601 → 模块 Running -32001 → 参数 -32602 → 口令 -32002 → 限流 -32003 → 执行超时 -32004/内部 -32010，异常绝不逃逸）；`CommandRateLimiter`（能力+来源维度固定窗口，时钟可注入）；`CommandAudit`（单行 JSON 落 `ipc-audit.log`，超 1MB 轮转，参数只记 SHA-256 摘要，口令原文绝不落盘）。`ModuleManager` 新增 `CollectCommands()`/`GetModuleStatus()`（pull 收集，逐模块异常隔离）；`App` 启动时装配并注册单例。内核只认原始 CLR 类型参数； RequiresPin 能力经 `PinGuard` 校验（复用宿主失败限流），口令由请求内联携带（v1.2「口令即确认」），无 PinGuard 时 fail closed。
- **S2 命名管道传输**（`src/Host/Ipc/`）：`FrameCodec`（[int32 LE][UTF-8 JSON]，1MB 上限，超限断开）；`RpcProtocol`（JSON-RPC 2.0 映射，`pin`/`source` 为协议扩展字段且不进参数摘要）；`NamedPipeCommandServer`（`PipeSecurity` 仅授当前用户 SID + SYSTEM；accept 循环 + 每连接独立任务；管道名带用户 SID）。`host.hello/host.status/host.modules.list/host.capabilities.list` 四个宿主能力（含能力表哈希，供客户端缓存）。`AppSettings` 新增 `Ipc { Enabled, PipeName, AuditEnabled }` 节，`CopyTo`/`Merge` 同步深拷贝（附回归测试）。
