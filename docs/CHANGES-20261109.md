## 2026-11-09 22:27:45 — feat(task-scheduler): 大盘列重构（PID/已运行/内存占用独立成列，启用·常驻改是/否）

任务管理窗口（`TaskManagerWindow`）表格按可读性重排，运行态不再把 PID 与秒数挤在一列：

- **列结构**（10 列）：运行状态 · PID · 已运行 · 任务名称 · 启用 · 常驻 · 触发方式 · 内存占用 · 执行动作 · 最近结果。窗口默认宽 980 → 1150（MinWidth 840 → 960），列宽合计 1035，默认宽度下无横向滚动。
- **运行状态** 只保留状态文字（运行中 / 启动中 / 停止中 / 等待重试 Ns / 熔断保护 / 空闲），并发多实例显示"运行中 ×N"；PID 与时长各自独立成列，`--` 表示不适用。
- **已运行** 改人类可读格式：`45 秒` / `12 分 30 秒` / `3 小时 7 分` / `2 天 8 小时`（`TaskRowViewModel.FormatDuration`，1s 心跳仅重排字符串）。
- **模式列 → 常驻**：值改 `是/否`（`options.mode=detach`），原"常驻守护/单次运行"文案取消。
- **启用列** 值改 `是/否`，保留绿/灰徽标样式。
- **新增内存占用列**：进程物理工作集（`Process.WorkingSet64`，与任务管理器"内存"同口径），单位 KB/MB/GB，读取失败显示 `--`。
- **性能数据按需读取**：新增 3s `_perfTicker` 采样器，仅当窗口 `IsVisible && WindowState != Minimized` 时读取内存；最小化即停止 1s 心跳与 3s 采样（`UpdateSamplingActivity`），窗口关闭时全部停止。采样在线程池执行后回投 UI 线程，含并发保护，不阻塞界面；后台常驻/托盘路径完全不读取进程性能数据。
- **实现要点**：`ReadWorkingSetBytes` 刻意不调用 `Process.HasExited`——该属性需 SYNCHRONIZE 权限，对部分受限进程抛"拒绝访问"，会把本可读的工作集误判为不可读（实测复现并修复）。
- **验证**：`dotnet build` 0 警告 0 错误；`dotnet test` 411 通过 / 0 失败（新增 `TaskRowFormatTests` 6 项覆盖时长与字节格式化）；界面用临时预览器（`temp/uipreview`，隔离 `CARRODESK_DATA_DIR`）渲染截图核对列宽、PID、时长与内存数值。
