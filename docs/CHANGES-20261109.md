## 2026-11-09 23:18:13 — fix(task-scheduler): 采样生命周期与测试运行治理（review 第一批 · 批次2）

- `TaskManagerWindow`：新增 `_closed` 门闩与 `TryPost()` 统一 Dispatcher 回投（状态回调不再因 Dispatcher shutdown 抛未处理异常）；最小化/关闭时 `CancelInFlightSampling()` 取消已在飞行的采样轮次，兑现「后台零读取」；采样改为「任务名 + PID」快照 + 代际校验，结果按名称回投到当前列表项（列表重建后不再写孤立 ViewModel），过期结果丢弃；单飞标志挡住的立即补采改为 `_pendingResample` 标记，回投后补一轮而非静默吞掉；CTS 每轮释放。
- `TaskManagerWindow`：搜索框 `TextChanged` 改 200ms 防抖，不再逐字符整表重建与触发采样。
- `TaskEditDialog`：detach 测试启动时保持「停止」态并禁止再次测试，避免覆盖 `_testRunHandle` 导致旧常驻进程脱管；wait 模式用局部 `cts`（不再引用可能被 `OnClosing` 置 null 的 `_testCts`）、`IsLoaded` 门闩避免写已关闭窗口控件，测试结束释放 CTS；`OnClosing`/`OnTestStopClick` 统一先 Cancel 再 Dispose。
- `TaskEditDialog`：修复 `KillWithHost = isDetach && ...` 回归——wait 模式恒 false 会让任务进程脱离宿主 Job Object，宿主退出后继续存活却不再被跟踪；现按复选框持久化（默认 true）。
- 验证：`dotnet build` 0 警告 0 错误；`dotnet test` **415 通过 / 0 失败 / 0 跳过**。

## 2026-11-09 23:13:56 — fix(task-config): 任务配置数据保护（review 第一批 · 批次1）

- `TaskConfigService.Load`：把文件读取从解析流程中拆出，`IOException` / `UnauthorizedAccessException` 等瞬时 IO 与权限异常不再进入「损坏自愈」，避免一次读失败就把完好的 `tasks.json` 备份后重写为 `[]`；新增 `internal ShouldRecoverFromCorruptFile(Exception)` 供纯逻辑测试覆盖该分支。
- `TaskLoadResult` 新增 `ReadOnly` / `ReadOnlyReason`：更高 schema 版本、空文件、部分任务校验失败或被跳过时标记只读，磁盘文件保持原样。
- 新增 `Save(tasks, baseline, out error)` 带基线保存：只读基线直接拒绝；保存前比对磁盘原文，检测到本次打开后被外部修改（手改 / 远程下发 / 其它实例）时拒绝整表覆盖并给出可展示原因，磁盘内容一字不变。旧 `Save(tasks)` 保持兼容，调度器与既有测试不受影响。
- `TaskManagerWindow`：`LoadTasks` 保存加载基线；顶部新增「加载异常横幅」，仅在配置有问题时出现（非模态、不弹窗打扰），文案说明只读或备份位置；`SaveTasksAndNotify` 改走带基线保存，被拒绝时只提示一次并保留用户内存态，不再 Reload / 误报「保存失败」。
- 测试：`ConfigPersistenceTests` 新增 4 项（IO 异常不触发自愈、只读基线拒绝保存、外部修改拒绝保存、正常基线允许保存）。
- 验证：`dotnet build` 0 警告 0 错误；`dotnet test` **415 通过 / 0 失败 / 0 跳过**。

## 2026-11-09 22:27:45 — feat(task-scheduler): 大盘列重构（PID/已运行/内存占用独立成列，启用·常驻改是/否）

任务管理窗口（`TaskManagerWindow`）表格按可读性重排，运行态不再把 PID 与秒数挤在一列：

- **列结构**（10 列）：运行状态 · PID · 已运行 · 任务名称 · 启用 · 常驻 · 触发方式 · 内存占用 · 执行动作 · 最近结果。窗口默认宽 980 → 1150（MinWidth 840 → 960），列宽合计 1035，默认宽度下无横向滚动。
- **运行状态** 只保留状态文字（运行中 / 启动中 / 停止中 / 等待重试 Ns / 熔断保护 / 空闲），并发多实例显示"运行中 ×N"；PID 与时长各自独立成列，`--` 表示不适用。
- **已运行** 改人类可读格式：`45 秒` / `12 分 30 秒` / `3 小时 7 分` / `2 天 8 小时`（`TaskRowViewModel.FormatDuration`，1s 心跳仅重排字符串）。
- **模式列 → 常驻**：值改 `是/否`（`options.mode=detach`），原"常驻守护/单次运行"文案取消。
- **启用列** 值改 `是/否`，保留绿/灰徽标样式。
- **新增内存占用列**：进程物理工作集（`Process.WorkingSet64`，与任务管理器"内存"同口径），单位 KB/MB/GB，读取失败显示 `--`。
- **性能数据按需读取**：新增 3s `_perfTicker` 采样器，仅当窗口 `IsVisible && WindowState != Minimized` 时读取内存；最小化即停止 1s 心跳与 3s 采样（`UpdateSamplingActivity`），窗口关闭时全部停止。采样在线程池执行后回投 UI 线程，含并发保护，不阻塞界面；后台常驻/托盘路径完全不读取进程性能数据。
- **实现要点**：`ReadWorkingSetBytes` 刻意不调用 `Process.HasExited`——该属性需 SYNCHRONIZE 权限，对部分受限进程抛"拒绝访问"，会把本可读的工作集误判为不可读（实测复现并修复）。
- **验证**：`dotnet build` 0 警告 0 错误；`dotnet test` 411 通过 / 0 失败（新增 `TaskRowFormatTests` 6 项覆盖时长与字节格式化）；界面用临时预览器（`temp/uipreview`，隔离 `CARRODESK_DATA_DIR`）渲染截图核对列宽、PID、时长与内存数值。
