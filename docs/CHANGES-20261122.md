# 变更记录 2026-11-22

> 本文件按时间倒序记录 2026-11-22 的重点变更。

## 2026-11-22 12:03:04 — refactor(tasks): 运行日志改为按月合并存储并修复右键查看日志定位

- **按月合并日志**：
  - 任务运行日志路径由 `runs/<task>/<yyyyMM>/<runId>.log`（单次运行一个文件）精简为 `runs/<task>/<yyyyMM>.log`（每个任务每月一个日志文件）。
  - 去除不必要的按月子目录层级，当月多次运行的 `=== RUN START ===`、命令、输出、`=== RUN END ===` 顺次追加至同一个月度日志文件中，彻底解决日志文件过于细碎的问题。
  - 同步保留唯一 `runId` 与 `history.jsonl` 事件索引能力，不破坏运行历史查询与单次输出 10MB 截断等安全护栏。
- **修复右键查看日志定位与路径**：
  - 新增 `TaskLogPaths.FindLatestLogFile(taskName)`：优先扫描 `runs/<task>/` 目录下所有 `*.log` 文件（按 `LastWriteTimeUtc` 倒序选取真正最新的日志文件），兜底兼容当月日志与旧版 `logs/task-<name>.log`。
  - `RunHistoryStore.GetLatestRunLogPath` 改为基于上述逻辑进行真实磁盘探测，不再因为 `history.jsonl` 缺少条目或条目记录被移走而返回 `null`。
  - 任务列表右键「📄 查看任务日志」及工具栏「📄 日志」在任务尚未产生任何日志时，提示文案显示预期的完整月度日志文件路径（`runs/<task>/<yyyyMM>.log`），消除路径模糊问题。
  - 运行历史窗口双击行打开日志时增加相同 fallback，旧单次运行文件被清理时回退至最新可用日志。
- **完善月度日志保留与清理机制（Prune）**：
  - 修正共享月度日志清理逻辑：由于当月多次运行共享同一文件，单个历史运行记录淘汰时，只要当月还有其他保留记录，绝不误删该月度日志文件；只有该文件不再被任何保留记录引用时才安全删除。
  - 修复 `Prune` 中总存储容量计算按唯一物理文件去重统计，避免同月多次运行重复计算文件大小。
- **测试与验证**：
  - 更新 `TaskLoggingTests`：验证同一任务当月运行追加至同一月度日志、验证部分历史记录淘汰时共享月度文件不被误删、验证自动定位最后修改时间最新的日志文件。
  - 541 项单元测试全部通过（新增 2 项测试），Release 构建 0 警告 0 错误。
