# 自动化任务管理架构与界面体验全盘重构方案 (v2)

- **文档标识**：`docs/TASK-MANAGEMENT-REFACTOR-PLAN-20261008-v2.md`
- **日期**：2026-10-08
- **背景**：针对现有任务编辑器“列表、表单与繁杂底栏混杂难用”、“编辑状态与列表切换冲突”、“托盘层级冗长嘈杂”等根本性体验缺陷，进行全盘解耦与重构设计。
- **核心指导思想**：
  1. **分治解耦**：将“大盘任务管理”与“单任务参数编辑”彻底分离为两个专注的窗口；
  2. **类任务计划但更好用**：主面板提供现代化、高信息密度的行式任务大盘，操作集中在顶部工具栏与右键菜单，底栏回归极简状态栏；
  3. **显式保存契约**：编辑任务使用独立对话框，只有显式点【保存】才生效，彻底终结“切换列表覆盖未保存改动”的痛点；
  4. **托盘极简化**：精简重载与日志目录等低频噪音项，去除非交互的“最近运行”占位，收敛“手动运行”，强化“运行中任务”实时感知与启停。

---

## 一、界面与交互重构：双窗口分治体系

### 1. 任务管理主窗口 (`TaskManagerWindow`)：大盘总览与集中管控

借鉴现代 Windows 任务计划程序与云原生 Dashboard 的优点，以**全景列表 + 顶部动作栏 + 快捷右键**为主体架构。

#### 1.1 界面布局规划
```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│  任务管理 (Task Manager) - CarroDesk                                            —  □  × │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  [➕ 新建]  [▶ 运行]  [⏹ 停止]  [🔄 重启]  [✏️ 编辑]  [📄 日志]  [🗑️ 删除]  │ 🔍 搜索过滤... │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  状态 │ 启用 │ 任务名称与说明        │ 触发规则          │ 执行目标 (Action) │ 模式  │ 上次运行    │
├───────┼──────┼───────────────────────┼───────────────────┼───────────────────┼───────┼─────────────┤
│  🟢   │ [✓]  │ frpc-daemon           │ [启动 +10s] 守护  │ frpc.exe -c ...   │ 常驻  │ 10:00:00 成功│
│       │      │ 远程内网穿透客户端守护  │                   │                   │       │             │
│  ⚪   │ [✓]  │ daily-backup          │ [每天 03:00]      │ backup.py --all   │ 标准  │ 昨天 成功(0) │
│       │      │ 全量数据压缩归档      │                   │                   │       │             │
│  🟡   │ [✓]  │ sync-api-job          │ [间隔 30m] 待命中 │ sync.js (2s后重启)│ 常驻  │ 14:20:11 异常│
│  🔴   │ [✓]  │ bad-script            │ [启动] 熔断       │ error.bat         │ 常驻  │ 12:00:05 熔断│
│  ⚪   │ [ ]  │ old-cleaner           │ [手动]            │ clean.ps1         │ 标准  │ -           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  [✓] 自动化调度总开关 (运行中)     │ 统计：共 5 个任务 · 1 个正在运行 · 1 个已禁用           │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 1.2 主大盘核心特性
1. **高信息密度任务列表 (DataGrid / ListView)**：
   * **状态列 (Status)**：
     - 🟢 **运行中**（ToolTip 显示 PID、已运行时长、内存等）；
     - 🟡 **守护重试中**（ToolTip 显示已失败次数、下一次重启倒计时）；
     - 🔴 **已熔断失败**（连续失败耗尽预算，等待人工干预）；
     - ⚪ **空闲 / 未运行**。
   * **启用列 (Enabled)**：
     - 单击直接切换 CheckBox，立即异步持久化并热重载生效；
     - 禁用时整行名称和图标置灰（透明度 50%），状态区分极其分明。
   * **任务名称与描述列 (Name & Description)**：
     - 第一行：加粗显示任务名称（如 `frpc-daemon`）；
     - 第二行：次级灰字显示备注说明（如 `远程内网穿透客户端守护`），解决“光看名字记不住用途”的问题。
   * **触发规则列 (Trigger Badge)**：
     - 语义化彩色徽标：`[启动 +10s]`、`[每日 09:00]`、`[间隔 1h]`、`[监听 Downloads]`、`[热键 Ctrl+Alt+Q]`、`[手动]`。
   * **上次运行列 (Last Run)**：
     - 显示上次执行时间和状态标签（如 `今天 14:30 成功`、`昨天 失败:1`），鼠标悬停显示详细耗时与返回码。
2. **快捷操作体系**：
   * **双击某一行**：直接呼出独立的【任务编辑窗口】；
   * **选中行时的工具栏联动**：
     - 空闲任务：【运行】高亮启用，【停止/重启】禁用；
     - 运行中任务：【停止/重启】高亮启用，【运行】禁用；
   * **完备右键上下文菜单 (ContextMenu)**：
     - `▶ 立即运行`（若已运行则提示或置灰）
     - `⏹ 停止任务`（杀进程树并取消守护挂起）
     - `🔄 重启任务`（先停止并立刻重新拉起）
     - `──────────────────`
     - `✏️ 编辑任务...`（打开独立编辑弹窗）
     - `📋 复制任务`（基于当前任务快速克隆）
     - `📄 查看该任务日志`（内置日志抽屉或弹窗查看）
     - `📂 打开所在目录`（定位到关联脚本所在路径）
     - `──────────────────`
     - `🗑️ 删除任务`（二次确认防误删）
3. **底栏彻底净化**：
   * 去掉所有“测试运行”、“停止测试”、“校验”、“仅保存”、“保存并生效”等杂乱按钮；
   * 仅保留全局总调度开关和轻量实时汇总（如 `共 8 个任务 · 2 个运行中`）。

### 2. 独立任务编辑面板 (`TaskEditDialog`)：专注、安全与显式契约

彻底终结“改一半点错列表导致内容丢失”的痛点。编辑/新建是一个完全独立的模态对话框。

#### 2.1 界面布局规划
```
┌─────────────────────────────────────────────────────────────┐
│  编辑任务 - frpc-daemon                              [×]    │
├─────────────────────────────────────────────────────────────┤
│  ┌─ 基础信息 ─────────────────────────────────────────────┐ │
│  │ 任务名称: [ frpc-daemon       ]  [✓] 启用该任务        │ │
│  │ 备注说明: [ 远程内网穿透客户端守护                   ] │ │
│  └────────────────────────────────────────────────────────┘ │
│  ┌─ 触发规则 ─────────────────────────────────────────────┐ │
│  │ 触发类型: [ startup - 系统启动/运行后延迟          ▼ ] │ │
│  │ 延迟时间: [ 10   ] 秒                                  │ │
│  └────────────────────────────────────────────────────────┘ │
│  ┌─ 执行动作 (Action) ────────────────────────────────────┐ │
│  │ 执行文件: [ frpc.exe           ] [浏览] [scripts快速选择]│ │
│  │ 启动参数: [ -c {{dir}}/frpc.toml ] [插入模板...]       │ │
│  │ 工作目录: [                    ] [浏览] (留空为脚本目录) │ │
│  │ 环境变量: [ + 添加自定义环境变量 (Env)               ] │ │
│  └────────────────────────────────────────────────────────┘ │
│  ┌─ 运行模式与选项 ───────────────────────────────────────┐ │
│  │ 运行模式: ( ) 标准执行 (等待退出)  (•) 后台常驻 (detach) │ │
│  │ [✓] 随宿主退出终止 (KillWithHost)                      │ │
│  │ [✓] 异常退出自动守护重启 (每隔 [ 5 ] 秒，最多 [ 3 ] 次)│ │
│  │ [✓] 隐藏窗口                                           │ │
│  └────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│  [⚡ 测试试跑]                      [ 取消 ]  [ 确定保存 ]   │
└─────────────────────────────────────────────────────────────┘
```

#### 2.2 核心交互设计
1. **显式保存契约 (Explicit Save)**：
   * 点击【确定保存】：执行表单完整语义校验，通过后自动写入 `tasks.json` 并通知主窗口及调度器热生效，关闭弹窗；
   * 点击【取消】或右上角关闭：若表单有变动，轻量提示“放弃本次修改？”，点击确认则原样退出，**内存与磁盘零污染**。
2. **就地“测试试跑”能力**：
   * 在弹窗左下角提供【⚡ 测试试跑】；
   * 点击后直接以当前表单的未保存临时参数在后台跑一次，并在弹窗底部浮动展开一个小巧的控制台输出回显框（包含耗时、退出码与 stdout/stderr 摘要）；
   * 用户在弹窗里就能直观确认参数对不对、脚本能不能跑通，调试完毕满意后再点【确定保存】。

## 二、托盘菜单全盘精简与优化重构

用户反馈指出的关键点：
* 当前托盘菜单把低频操作（“重载任务”、“打开任务日志目录”）堆在一级，产生视觉干扰；
* “最近运行”展开全是一堆灰色的静态时间戳字符串，不能点击交互，浪费菜单空间；
* “手动运行”平铺展开所有已启用任务，任务较多时菜单被拉得极长。

### 1. 托盘菜单新旧对比

| 菜单项 | 现状 | 新设计 | 决策理由 |
|---|---|---|---|
| **任务管理器入口** | `任务编辑器...` | **`任务管理...`** (加粗第一项) | 明确作为主要大盘入口，点击呼出全景主窗口 |
| **总开关** | `启用任务调度` (勾选) | 保留 `[✓] 启用任务调度` | 保持快速暂停/恢复所有计划任务的高频能力 |
| **运行中实例监控** | **无** | **新增 `运行中任务 (N)` 动态分组** | 实时查看当前正在跑的任务；二级展开提供【⏹ 停止】、【🔄 重启】 |
| **手动触发** | `手动运行` (平铺所有已启用任务) | **优化为 `手动任务 (N)` 或 `快捷运行`** | **仅展示触发类型为 `manual` 的任务**（或带全局热键的任务）；普通定时/监听任务统一由主窗口管理，不再无限膨胀 |
| **最近运行** | `最近运行` (10条只读灰色时间戳) | **彻底移除** | 只读纯文本毫无交互价值；主窗口列表中有明确的“上次运行”与结果列，信息更丰富 |
| **打开日志目录** | `打开任务日志目录...` | **彻底移除** | 极低频；主窗口和独立编辑面板已自带日志查看能力 |
| **重载任务** | `重载任务` | **彻底移除** | 保存任务和启闭开关均会自动热重载；若外部手改了 json，主窗口亦有 F5 刷新，不再占用托盘一级空间 |

### 2. 重构后的托盘结构示意

```
[CarroDesk 托盘图标]
  └─ 自动化任务 (运行中)
       ├─ 任务管理...                           <-- 呼出 TaskManagerWindow 主面板
       ├─ [✓] 启用任务调度
       ├─ ────────────────────────────
       ├─ 运行中任务 (1)                        <-- 仅在有任务运行时展开；无任务时可隐藏或灰显
       │    └─ frpc-daemon (pid: 14280, 2h)
       │         ├─ ⏹ 停止
       │         └─ 🔄 重启
       ├─ 手动任务 (2)                          <-- 仅枚举 trigger.type == manual 的快捷启动项
       │    ├─ quick-notepad
       │    └─ backup-now
       └─ ────────────────────────────
```

## 三、底层支撑能力配套设计（针对 一1, 二1~3, 三1~3）

为了支撑上述现代化界面的可靠运行，底层核心按前述分析配套就位：

### 1. 运行态感知与存活性校验
* `ITaskSchedulerService` 暴露 `TaskStateChanged` 事件与 `TaskRuntimeState` 枚举；
* 主面板通过订阅事件实现状态毫秒级点亮与熄灭；
* 增加心跳存活检查，杜绝外部被杀导致的“假运行”与“假绿灯”。

### 2. 触发器增强
* **文件监听 (Watch)**：`TemplateExpander` 注入 `{{file}}`、`{{fileName}}`、`{{fileDir}}`；增加文件写锁 3 秒排队就绪检测；
* **每日定时 (Daily)**：增加 `CatchUpOnStartup` 开机晚点自动补偿执行，记录 `LastFiredTime`，彻底解决非 24 小时开机用户漏跑问题；
* **周期循环 (Interval)**：增加 `RunAtStartup` 开机即执行一次支持；休眠唤醒（`Resume`）根据实际时间差对齐并补偿。

### 3. 执行引擎加固
* **常驻进程跨重启防重 (SingleInstance)**：通过 `tasks.state.json` 记录 PID、进程启动时间与可执行文件路径，宿主启动时核验存活并接管，杜绝双实例；
* **编码自适应**：批处理与控制台工具自动匹配系统 OEM 代码页（CP936/GBK），彻底消除日志中文乱码；
* **自定义环境变量**：支持任务级 `env` 键值对注入。

## 五、方案总结与对比提升

| 维度 | 现状痛点 | 重构后体验 |
|---|---|---|
| **信息架构** | 列表、几十个表单控件、十几个底部按钮挤在一个窗口 | **大盘总览窗口** 与 **独立编辑对话框** 职责清晰分离 |
| **运行状态感知** | Enabled 勾选就常亮绿灯 🟢，关了还显示启动 | 严格按实际进程运行态呈现：🟢运行(带PID)/⚪空闲/🟡守护/🔴熔断 |
| **进程操作掌控** | 只有试跑，无法直接运行，停止隐藏深，无重启 | 主面板与右键一键：**【▶ 启动】、【⏹ 停止】、【🔄 重启】** |
| **编辑防误触** | 切列表或点新增，未保存内容静默覆盖丢失 | 独立弹窗模态编辑，只有点【保存】才生效，取消零污染 |
| **托盘体验** | 堆满静态时间戳、低频重载项、平铺长菜单 | 仅保留“任务管理”、运行中任务监控、手动快捷项，极简高效 |
| **自动化能力** | 文件监听拿不到文件名、关机晚开漏跑任务 | 支持 `{{file}}` 变量、开机自动补跑、周期启动即跑、OEM防乱码 |
