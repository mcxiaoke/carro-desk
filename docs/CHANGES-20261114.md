## 2026-11-14 18:54:38 — feat(tasks): 新增任务级触发频率限制核心与持久化状态

- 新增 `src/Modules/TaskScheduler/Services/TaskFireLimiter.cs`：按任务名聚合的当日计数与最短间隔限流；`CanFire`（只读，供 idle 前移判定）与 `TryAcquire`（锁内原子检查并消耗）共用判定内核；`ForgetRemovedTasks` 清理孤儿条目；`GetSnapshot` 供排障读取。
- 状态落盘 `task-fire-state.json`（`AtomicFile` 原子写、延迟读回、UTC ticks 存时间戳）：沿用 `PinGuard` 范式，损坏/版本不识别则备份原件 + 清空计数 + 立即回写合法空状态，落盘失败降级为进程内计数并记 WARN，绝不阻断任务执行。
- 边界处理：本地自然日归零、UTC 最短间隔、系统时钟回拨自动重置并放行、默认策略零落盘零日志。`IsUserDrivenReason` 用前缀匹配，兼容 `HotkeyTrigger` 的 `"hotkey:<组合键>"` reason（既有 `ExecuteAsync` 精确匹配偏差不做改动，见设计文档附录 B）。
- 刻意不依赖 `TaskOptions` 新字段，策略由调用方经 `FireLimitPolicy` 传入，保证本批可独立编译，也为后续任意触发器复用留出接口。
- 新增 `tests/CarroDesk.Tests/TaskFireLimiterTests.cs`（11 项）：默认零开销、每日上限、跨天归零、间隔边界、回拨、并发原子性、重启读回、损坏文件降级、孤儿清理、`CanFire` 不消耗、人工 reason 前缀。
