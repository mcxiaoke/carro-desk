## 2026-11-14 19:05:27 — feat(tasks): idle 冷却/额度恢复后自动补触发

- `IdleTrigger` 增加可选的 `TaskFireLimiter` 构造注入（策略从 `task.Options` 读取），在 `OnIdleTick` 置位 `_fired` **之前**调用只读 `CanFire`：被拒时保持 `_fired == 0`，每秒一次的 `IdleTick` 继续询问，冷却或跨天额度恢复后若用户仍处于空闲即自动补触发，无需再经历「回座 → 离开」；`_fired` 仍保证每个空闲周期只跑一次。
- `CanFire` 不消耗配额，消耗仍统一由服务层 `OnTriggerFired` 的 `TryAcquire` 完成，因此**无需为 idle 开重复计数特例**；`CanFire → Fired → OnTriggerFired` 是同一线程同步链，无并发插入窗口。未注入 limiter 时行为与改动前完全一致（既有并发/重新武装单测不改）。
- 拒绝日志按「refusal 变化或距上条 ≥ 60s」限频并加锁保护，避免 1s 一 tick 刷爆 5MB 轮转日志。
- `CreateTrigger` 的 idle 分支注入服务层的同一个 limiter 实例，保证触发器与服务层共享同一份额度状态。
- 新增 `tests/CarroDesk.Tests/TaskFireLimitIdleTests.cs`（4 项）：无 limiter 旧行为回归、冷却内延迟且到点自动补触发、当日额度用尽跨天自动补触发、120 次拒绝 tick 的日志限频。

## 2026-11-14 19:01:50 — feat(tasks): 服务层接入触发限流统一门

- `TaskSchedulerService` 新增由构造注入的 `TaskFireLimiter` 单例（默认落盘 `DefaultStatePath`），状态不随触发器重建而丢失；`ApplyCoreLocked` 只调 `ForgetRemovedTasks` 清理已删除任务的条目，**绝不清空额度**，并放在 `_lock` 之外避免锁内文件 IO。
- `OnTriggerFired` 在既有 startup/daily 会话记录之后、`Task.Run(ExecuteAsync)` 之前插入统一门：被限流记 `skipped(<reason>) fire limit: ...` 并 `AddRecent("throttled")` 后 return，不进入 FSM。被限流的 `startup:catchup` 仍记为「本会话已尝试补跑」，语义与 `_firedStartupTasks` 一致。
- 新增 `internal TryPassFireLimit(task, reason, out refusal)` 统一策略分流：`limitScope=auto` 时人工类（manual/restart/hotkey 前缀）绕过且不消耗额度，`all` 时全部受限；默认不限流策略零开销直接放行。
- 补齐两个旁路：`RunManual` 与 `RestartTask` 在启动前同样过门（`RestartTask` 在同步入口判定，被拒时不会先停掉旧实例）；`retry` 与 detach 守护重启不经门、不消耗配额（同一实例的恢复）。
- 新增 `tests/CarroDesk.Tests/TaskFireLimitDispatchTests.cs`（6 项）：自动触发消耗额度、auto 人工绕过、all 人工受限、**Reload 后额度不丢且不多给一轮**、补跑受限、默认策略恒放行。
