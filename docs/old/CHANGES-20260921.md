# 变更记录

## 2026-09-21 11:18 — Awake：智能进程联动新增总开关

**背景**：智能进程联动（检测到名单中的进程运行时自动保持唤醒）此前只能通过清空进程名单来"停用"，用户想临时关掉联动就必须删掉配置好的名单，无法保留。本次补上独立总开关。

**配置层（`AwakeConfig`）**
- 新增 `ProcessLinkEnabled`（默认 `true`，保持既有行为不变）。关闭时 `AutoAwakeProcesses` 名单与 `AutoAwakeExitDelaySeconds` 退出缓冲时间**原样保留**，仅暂停联动行为。

**服务层（`AwakeService`）**
- 新增只读属性 `IsProcessLinkEnabled` / `HasProcessTargets`，把"是否该跑联动"的判断收敛到一处。
- 轮询入口改用上述属性把关，开关关闭时**完全不进入**进程检测（不再每 5 秒枚举一遍进程）。
- `CheckProcessTriggers` 入口加早退守卫，使反射直调路径（测试）同样尊重开关。
- `UpdateConfig` 中处理"运行中关闭开关"：立即撤销正在进行的联动（清 `_isProcessTriggered` / `_activeProcessTrigger` / `_processExitPendingSeconds`，并把联动独占的 `Indefinite` 模式回落到 `Passive`），避免留下"已关闭却仍在保持唤醒"的残留状态，并发出 `ProcessTriggered(false, ...)` 让 UI 与托盘同步。仅回落到 `Passive` 时不影响用户手动设置的 `Timed`/`UntilTime`。

**托盘（`AwakeModule`）**
- 二级菜单新增可勾选项 `awake_process_link`「智能进程联动」，与"保持屏幕常亮"同为复选开关，一键启停并即时落盘。
- 新增 `ToggleProcessLink()` / `SetProcessLinkEnabled(bool)`：切换后调用 `Service.UpdateConfig` 立即生效、`SaveConfig` 落盘、刷新托盘；并给出区分场景的气球提示（启用/停用，以及启用但名单为空时的引导）。
- 开关的 `ToolTip` 按当前状态动态说明含义。

**设置界面（`AwakeSettingsWindow`）**
- 卡片 3 标题行右侧新增「启用」总开关；关闭时进程名单区整体置灰（`IsEnabled=false` + 半透明）并显示橙色说明"名单与缓冲设置仍然保留"，让"保留配置、仅暂停行为"的语义一眼可见。
- 总开关变化只做界面预览，实际生效仍走「保存并应用」；「恢复默认」一并复位该开关。

**i18n**：`zh-CN` / `en-US` 各补 6 个 key（`AwakeProcessLinkOn` / `TipOn` / `TipOff` / `OnNotify` / `OnNoTargets` / `OffNotify`）。

**测试**：新增 2 个用例——`Awake_ProcessLinkDisabled_SuppressesAutoTrigger`（关闭时不触发、重新启用后恢复联动）、`Awake_DisablingProcessLink_RevokesActiveLink`（联动中关闭开关须立即撤销且不被后续轮询反转）；并在既有默认值/托盘结构用例中断言新开关的默认值与节点存在。

**验证**：`dotnet build` 0 警告 0 错误；全量 **183** 项测试通过（原 181 + 新增 2）。界面经临时 `CARRODESK_UI_DEBUG` 钩子实机渲染截图核对启用/停用两态，无截断、重叠或越界，停用态置灰与橙色提示均正确，名单条目保留可见；验证后该临时代码已移除。
