## 2026-09-19 22:47 — 代码审查 P0/P1 修复（批次 6）：Cron 漏触发与 DOM/DOW 语义

- **P1-5 修复 Cron 漏触发：改为精确定时到下一次触发点** (`CronTrigger.cs`)：
  - 根因：原实现每 30 秒用 `IsMatch(DateTime.Now)` 判断"当前这一分钟"，只认当前分钟且**没有任何补触发机制**——UI 线程一旦被阻塞超过 60 秒（弹窗、编辑器、GC 卡顿），该分钟的 Cron 任务被永久跳过且无日志。
  - 修复：计算下一次触发时刻并做一次性精确定时，触发后立即安排下一次；到点复检 `IsMatch` 以防御定时器提前唤醒与系统时钟回拨；`DispatcherTimer.Interval` 上限（约 24.8 天）之外的目标时刻先早醒再重算，使"每年 1 月 1 日"这类远期表达式同样可用；表达式合法但一年内不可达（如 2 月 30 日）时不再空转。
  - `CheckCatchUp()` 改为真正的漏触发补偿：记录当前定时器指向的目标时刻，休眠恢复后若已错过则立即补一次并以 `cron-catchup:` 作为触发原因（原先只是重新判断一次当前分钟，与注释宣称的语义不符）。
- **P1-5 修复 DOM/DOW 组合语义** (`CronHelper.cs`)：
  - 根因：`IsMatch` 与 `GetNextOccurrence` 都恒用"DOM 与 DOW 同时命中"，而标准 cron 在两者**都被限定**（非 `*`）时应为"或"。`0 9 1 * 1` 本意是"每月 1 号**或**每周一 09:00"，实际只在"1 号且是周一"触发，用户配置静默失效。
  - 修复：`CompiledCronExpression` 新增 `DayOfMonthRestricted`/`DayOfWeekRestricted` 标志与统一的 `IsDayMatch(dt)`；两者都限定时取"或"，否则取"与"（未限定字段掩码为全 1，因此"与"形式天然退化为只判断被限定的那个，既有行为完全不变）。
- **顺带加固** (`CronHelper.cs`)：
  - `Compile` 不再用 `GetOrAdd` 且不缓存无效表达式；编译结果缓存增加 256 条容量上限，防御异常输入造成的无界增长。
- **验证**：新增 5 个用例——DOM+DOW 同时限定的"或"语义（含正/反例）、单一限定时仍为"与"、`GetNextOccurrence` 取最近命中、不可达表达式返回 null、不可达表达式下 `CronTrigger` 不触发也不抛异常。既有 Cron 用例全部保持通过。

- **P0-4 修复 PROPVARIANT 结构尺寸不足导致的原生越界写** (`ComInterfaces.cs`)：
  - 根因：原生 `PROPVARIANT` 为 x86=16B / x64=24B（头部 8B + union 最大成员为计数数组，x64 下 16B），而原声明只到 `pwszVal`（x86=12B / x64=16B）。`IPropertyStore.GetValue` 按原生尺寸整体写回，**每次读取音频设备名都越界写 4/8 字节**。
  - 修复：显式 `Size = 24` 并对齐 union 偏移（`pwszVal` / `llVal` / `dblVal` 共用偏移 8）；`GetString()` 同时支持 `VT_LPWSTR` 与 `VT_BSTR`；`Clear()` 跳过 `VT_EMPTY`，其余仍交 `PropVariantClear` 按类型释放，避免改成"只处理字符串"而漏释放其它分配型。
  - 验证：新增 `ComInteropTests`，断言 `Marshal.SizeOf` 不小于原生尺寸、union 字段偏移为 8。
- **P1-2 修复任务执行的命令行注入与参数错拆** (`TaskRunner.cs` / 新增 `CommandLine.cs`)：
  - 根因：脚本包装是裸字符串相加（`"/c \"" + file + "\" " + args`）。`cmd.exe` 会对命令行做二次解析，参数中的 `& | < > ( ) ^` 被当作命令分隔符执行（例如 args 写成 `& calc.exe` 即造成任意命令执行）；路径含空格/引号时也会被拆错甚至闭合掉自己的引号。
  - 修复：新增纯函数类 `CommandLine`——`QuoteArgument` 按 `CommandLineToArgvW`/CRT 规则加引号（正确处理"引号前反斜杠翻倍"与"结尾反斜杠翻倍"这两个 Windows 经典坑）；`EscapeForCmd` 只转义**引号之外**的 cmd 元字符（引号内 cmd 本就不解释元字符，且补 `^` 会把 `^` 污染进参数值）。`.bat/.cmd` 改用 `cmd /S /c "..."` 保证最外层引号被正确剥离。
  - 验证：新增 `TaskRunnerTests` 真实启动脚本做端到端断言——`&`、`|`、`>`、`^`、`()`、含空格引号参数、含空格脚本路径均**原样到达脚本**，且参数中的 `>` 不再产生重定向文件。
- **P1-2 修复超时终止与孤儿进程** (`TaskRunner.cs` / 新增 `ProcessJob.cs`)：
  - 输出读取：移除跨线程累积的 `StringBuilder`（`stdout`/`stderr` 属数据竞态，且累积结果从未被使用，是死变量），只保留逐行落日志（`TaskLogger` 自身加锁）；把固定 `Task.Delay(100)` 改为无参 `WaitForExit()` 真正等待异步输出回调 flush，避免丢失脚本最后几行输出。
  - 超时：`timeoutSec * 1000` 改为 `TimeSpan.FromSeconds` 消除整数溢出；超时分支等待 `WaitForExit` 任务结束后再 Dispose，消除"在 WaitForExit 仍挂起时 Dispose 进程对象"的后台未观测异常。
  - 孤儿进程：新增 `ProcessJob`（Job Object 封装，`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），任务进程加入作业，超时终止或宿主退出时整棵子进程树被回收（原生调用全部失败降级，作业不可用不影响任务启动）。
  - 验证：新增超时用例真实启动阻塞脚本，断言返回 -1 且子进程确实死亡（按日志中的 pid 轮询确认），而不只是断言函数提前返回。
- **行为变更提示**：启用 kill-on-close 后，CarroDesk 退出会连带结束其仍在运行的任务进程树（这是"不留孤儿进程"的代价）。若希望长时任务跨宿主重启存活，可关闭该开关（`ProcessJob.TryCreate(killOnJobClose: false)`）。
