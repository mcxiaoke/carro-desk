# 变更日志 2026-10-07

## 23:27:00 迁移 .NET Framework 4.8 → .NET 10（分支 feat/net10-upgrade）

- 三个项目 TFM：`net48` → `net10.0-windows`（src/CLI/Tests），移除显式 `LangVersion 7.3`
- src csproj：Framework Reference（System.Management/System.Security/System.ServiceProcess）
  改为 NuGet 包 `System.Management` 10.0.12、`System.ServiceProcess.ServiceController` 10.0.12；
  显式 `SelfContained=false`（防止 CLI 单文件发布的 PublishSingleFile 流入引发 NETSDK1151）
- tests csproj：`System.ServiceProcess` Reference → NuGet 包
- **Costura.Fody 保留**（GUI 侧单文件嵌入在 .NET 10 上验证可用，Release 构建通过）
- **CLI 改用 PublishSingleFile 单文件发布**（Costura 无法再产出单 exe：apphost 必须携带
  dll/runtimeconfig），release.py 的 CLI 构建改为 `dotnet publish -r win-x64 --self-contained false
  -p:PublishSingleFile=true`，输出目录带 `win-x64\publish` 层
- release.py / CarroDesk.iss 中输出路径 `net48` → `net10.0-windows`
- 代码级修复：
  - `PinService.GenerateSalt`：废弃的 `RNGCryptoServiceProvider` → `RandomNumberGenerator`
  - `PinService.ComputeHash`：过时的 `Rfc2898DeriveBytes` 构造 → 静态 `Rfc2898DeriveBytes.Pbkdf2`（SYSLIB0060，行为不变）
  - `AudioService.SetDefaultPlaybackDevice`：移除 .NET Core 上无效的
    `HandleProcessCorruptedStateExceptions` / `SecurityCritical` 特性
  - `NamedPipeCommandServer`：net48 的 8 参 `NamedPipeServerStream` 构造 →
    `NamedPipeServerStreamAcl.Create`（ACL 语义不变）
  - `CommandHostTests`：采样线程由 `Thread.Interrupt` 改为 ManualResetEvent 结束
    （现代 .NET 将 Interrupt 异常按未处理异常处理，会崩测试主机）
- 验证：Debug/Release 构建通过（0 错误 0 警告）；**355 个单元测试全部通过**；
  net10 CLI 实测与运行中的 net48 宿主 IPC 兼容（host.status 正常返回）
- 注意事项：框架依赖发布的目标机器需安装 **.NET 10 桌面运行时**（本机已有 SDK 满足）；
  GUI/CLI 的运行时独立性与 net48 时代不同，见 docs/PLAN-UPGRADE-DOTNET10.md
